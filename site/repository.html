cybercore / dwcode · extensions

Your own extension repository.

DWCode hosts its own catalog of packs — curated, licence-checked and checksum-pinned — without borrowing anyone's marketplace. It opens below: 172 packages in 17 families, each one cleared by a licence gate that runs on every build. Underneath: what the licences allow, how the index is built, and the packages that stay out with the reason.

Every package, licence-checked.

Type to search names, publishers and ids; pick a family on the left; sort by downloads, name, licence or publisher. Install is disabled until milestone M5 publishes the checksum-pinned index — until then a card is a reviewed fact sheet, not a download button. The same run of npm run catalog:scan that fills this page is what fails a build when a licence is still pending.

// what a card carries Seven facts, all ours or all public: the package name, its Open VSX id, the publisher, the version, the licence, the download count, and a link to the publisher's own repository (falling back to the Open VSX entry when a publisher publishes no source). The one-line description under each name was written for this page — it is not listing text. The two-letter tile is generated from the id, so no publisher's artwork is copied, stored or hot-linked. Nothing here is a mirror: no binaries, no icons, no screenshots, no ratings, no endorsement. Names and counts describe what DWCode could index; every package stays the property of its publisher under the licence shown.

// 02 · how it works

An index you can verify offline.

No search API, no account, no telemetry: a static JSON index pinned by hash, fetched over HTTPS, re-validated in C++ before anything is enabled. The same rules the app already applies to packs/dwcode-core.

catalog/index.json
1{
2  "catalogVersion": 1,
3  "generated": "2026-10-26T00:00:00Z",
4  "packs": [
5    {
6      "id": "publisher.pack-name",
7      "version": "1.2.3",
8      "origin": "https://github.com/…/releases/download/v1.2.3/pack.dwcodepack",
9      "sha256": "9f2c…",
10      "license": "MIT",
11      "contributes": { "themes": 3, "snippets": 2, "icons": 7 }
12    }
13  ]
14}
1

Publish

Run the pack through npm run validate:packs, tag a release, upload the pack archive, and append its id, version, origin, sha256 and licence to the index. Recompute the index hash and sign or pin it.

2

Fetch and pin

DWCode downloads the index, checks it against the pinned hash, downloads one exact version of one pack, and writes origin + sha256 into the local lock record before anything is unpacked.

3

Re-validate, then enable

The C++ loader re-runs every rule — manifest version, engines range, path containment, token schema — regardless of what CI said. A pack only appears as enabled once you switch it on, licence and hash shown first.

// 03 · the licence gate

What the catalog accepts.

A licence field that is empty, a NOASSERTION, a SEE LICENSE IN … pointer at proprietary terms, or a custom LicenseRef means stop. Everything else is judged by what DWCode does with it: data it loads, or a process it launches.

ClassExamplesVerdictWhy
PermissiveMIT · Apache-2.0 · BSD · ISC · UnlicenseacceptRedistribute with the licence and notices intact; no further obligation.
Weak copyleftMPL-2.0 · EPL-2.0 · LGPL (separate files)acceptFile-level or dynamic-link obligations stay with the pack; record them in the pack record.
Strong copyleftGPL-3.0 (e.g. cSpell)data onlyThemes, snippets and grammars are data DWCode reads — fine to host. DWCode's binaries never link GPL code; GPL tools run as external processes with their own config.
Source-availablefreemium, "free tier", NOASSERTION (GitLens)refuseFree ≠ FOSS. No open-source grant means no redistribution right.
ProprietarySEE LICENSE IN → EULA, LicenseRef-…, licence NONErefuseNo grant to copy, host or index the binaries. Linking to the publisher's own page is the most DWCode may do.
Not on Open VSXMarketplace-only packagesout of reachDWCode's policy sources only from Open VSX or reviewed first-party packs. If the licence permits it, an original DWCode pack may be written from the source material — recreation, never bundling.

// 05 · submit a pack

Ship data, not code.

DWCode accepts declarative packs today: themes, icon maps, snippets, keymaps and syntax grammars. Anything with an executable entry point waits for the extension host.

  • Declarative only. manifestVersion: 1, kind: "declarative", no main or browser, and an empty capabilities array.
  • Open-source licence. An SPDX licence plus a licence file in the pack; every upstream asset you adapted must permit it, with attribution recorded.
  • Paths stay inside. Themes, icons and snippets are referenced relatively — ../ escapes and absolute paths are refused by the loader.
  • DWCode theme tokens. Imported colours are mapped into the surfaces / text / accents / syntax schema; application chrome always stays DWCode's.
  • Validate before you open the PR. npm run validate:packs runs the same schema, escape and entry-point checks CI will run.
  • Provenance. Upstream repository, version, licence and sha256 in the pack record — so a licence change later is a re-review, not a silent bump.

// 06 · allowed & credited

Allowed — on three conditions.

Nothing about running your own catalog conflicts with DWCode's MIT licence or with the licences of the packages it points at. The rules are the ones any distributor already has.

§

Licence-wise

DWCode is MIT, so it can publish any index it likes — that index is your work. Every pack it lists keeps its own licence: you redistribute the files exactly as upstream licensed them, with the licence text, notices and attribution intact. You never relicense a pack, and you never need permission to link to one.

allowedindex = yours
⎇

Open-source-wise

A repository is only an index plus files — no new policy to invent. The implementation is already specified as blueprint M5: a curated catalog published on GitHub Releases with a signed or checksum-pinned JSON index, exact-version installs, and origin + sha256 recorded in a lock record.

!

The three limits

Don't rehost proprietary packages — only index FOSS ones you were allowed to receive. Don't strip, alter or bury a licence or notice. And don't imply affiliation: this is not Open VSX, not the Visual Studio Marketplace, and not endorsed by Microsoft, the Eclipse Foundation or any upstream publisher.
